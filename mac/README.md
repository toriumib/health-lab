# ヘルスラボ Mac ツールキット

Apple ヘルスケアの書き出しを日別 CSV に整理し、生活リズムのカレンダーを作る小さな OSS ツールです。Python 標準ライブラリだけで動きます。アカウント、通信、常駐アプリ、Mac の設定変更はありません。実行した人が指定したファイルだけを読み書きします。

必要環境: Python 3.10 以上。`python3 --version` で確認します。macOS に Python がない場合は、このツール自体をインストール・実行できません。IANA タイムゾーン情報を使うため、`Asia/Tokyo` などが利用可能な環境が必要です。

## Apple ヘルスケア → 日別 CSV

iPhone のヘルスケアから自分のデータを書き出し、Mac に移した ZIP を展開して `export.xml` を用意します。ツールを展開したフォルダで、ターミナルから実行します。実際の XML の場所に置き換えてください。

```sh
python3 health_import.py "/path/to/apple_health_export/export.xml" --output "health-daily.csv"
```

作成されるファイル:

- `health-daily.csv`: `date,sleep_hours,steps,exercise_min,resting_hr,weight_kg,hrv_ms,note`
- `health-daily.sources.csv`: 日別・指標別に採用したデータソースと件数

`note` には採用ソース、日付の区切り、HRV の SDNN 定義を残します。ヘルスラボへ CSV を取り込む際も記録の由来を保持できます。

日付の境界は既定で **Asia/Tokyo の午前 0 時** です。XML の日時に付いた UTC オフセットを尊重してから指定タイムゾーンへ変換します。旅行先や別地域で整理する場合:

```sh
python3 health_import.py "/path/to/export.xml" --timezone America/New_York --output "health-daily.csv"
```

**データソースの選び方:** 同じ日・同じ指標では、重複を除いた有効なレコード数が最も多いソースを 1 つ選びます。同数ならソース名の Unicode 順です。Apple Watch と iPhone の歩数を足し合わせません。これは再現可能な簡易ルールで、機器の精度や品質を判定するものではありません。採用元を CSV で確認し、必要なら名前を指定します。

```sh
python3 health_import.py "/path/to/export.xml" \
  --source "steps=あなたの Apple Watch のソース名" \
  --source "sleep_hours=あなたの睡眠ソース名" \
  --output "health-daily.csv"
```

指定ソースにその日のデータがなければ空欄です。他のソースへ自動的に切り替えません。ソース名は XML の `sourceName`、または `health-daily.sources.csv` で確認できます。

表計算アプリでソース名が数式として実行されないよう、`=`・`+`・`-`・`@` などで始まる名前には出力時だけ先頭に `'` を付けます。その場合 `--source` には XML にある元の名前を指定してください。

集計方法と限界:

- **睡眠:** `Asleep`、`AsleepUnspecified`、`AsleepCore`、`AsleepDeep`、`AsleepREM` の時間帯を使います。採用ソース内の重なる時間帯は結合し、睡眠段階や同一時間帯を二重に加算しません。`InBed` と `Awake` は睡眠時間に加算しません。午前 0 時をまたぐ睡眠は日別に分割します。「昨夜の睡眠」とは集計単位が違います。複数ソースの時間帯も足し合わせません。
- **歩数・運動時間:** 採用ソースの有効値を合計します。午前 0 時をまたぐレコードは実経過時間の比率で按分します。歩数は元のレコードの総数を整数に丸め（小数 .5 は切り上げ）、時間比の累積値を丸めて日別に配分します。例えば 23 時〜翌 1 時の 3 歩は 2 歩・1 歩となり、分割しても総数 3 歩を保持します。区間内で均一に発生したという近似です。完全に一致するレコードは除きますが、異なるレコードの部分的な重複は判定できません。
- **安静時心拍・HRV:** 採用ソースの有効な測定値の単純平均です。HRV は Apple ヘルスケアの SDNN、単位は ms です。測定時刻、姿勢、機器、アルゴリズムが違う値をそのまま比較しないでください。
- **体重:** 採用ソースのその日最後の測定値を kg に変換します。同じ終了時刻では開始時刻が遅い値を選び、それも同じなら小さい数値を選びます。lb・g・oz も変換できます。
- 未記録の指標は **0 ではなく空欄** です。有効な対象レコードがある日だけ出力します。欠損日を補完しません。
- 未対応の種類、未対応単位、オフセットのない日時、不正な時間範囲、負値や無限大は取り込みません。件数をターミナルに表示します。ワークアウト、服薬、検査結果、睡眠診断、ヘルスケア側の集計優先順位は再現しません。
- XML を順次読み、重複確認と集計用データを一時 SQLite ファイルに置きます。全 XML をメモリに載せません。データ量に応じた一時ディスク空き容量が必要です。一時 DB は処理終了時に削除しますが、途中でプロセスを強制終了すると残ることがあります。保存先を指定する場合は `--temp-directory "/path/to/private-folder"` を使います。

この CSV は個人の機器データの整理であり、診断・治療判断・生物学的年齢の算出には使えません。日々の変化を振り返る補助として使い、測定条件と元データを一緒に確認してください。

## 生活リズム → Mac カレンダー用 ICS

通知を付けない、7 日分の予定ファイルを作ります。日付・時間は自身の生活に合わせて変更してください。既定の時刻は効果を保証する処方ではなく、編集用の初期値です。

```sh
python3 calendar_reminders.py --start-date 2026-09-30 --days 7 \
  --wake 07:00 --move-start 09:00 --move-end 18:00 --move-every 60 \
  --winddown 21:30 --output "health-lab-reminders.ics"
```

作る予定は、起床時刻の確認（10 分）、短い休憩・姿勢変更（5 分）、夜の過ごし方の確認（20 分）です。移動・休憩の開始時刻は `move-start` 以上、`move-end` 未満です。`--start-date` を省略すると指定タイムゾーンの当日になります。1〜366 日分を作れます。

```sh
# 必要な予定だけ作り、5 分前の通知をファイルに付ける
python3 calendar_reminders.py --wake none --move-every 0 --winddown 22:00 \
  --days 7 --alarm-minutes 5 --output "evening.ics"
```

- `--wake none` / `--winddown none`: その予定を作らない
- `--move-every 0`: 日中の休憩予定を作らない
- `--alarm-minutes 0`: 開始時刻の表示通知、`5` なら 5 分前。省略すると **VALARM なし**
- `--timezone Asia/Tokyo`: 日付と入力時刻を解釈する地域。ICS 内には UTC の日時を書きます。カレンダーの表示時刻は利用端末のタイムゾーン設定に従います。

生成後、Mac カレンダーの「ファイル → 読み込む」で `.ics` を選び、専用のカレンダーに取り込めます。**生成スクリプトは読み込み、通知許可、OS 設定変更を実行しません。** 取り込み先が iCloud や Google のカレンダーなら予定はそのサービスへ同期されます。ローカルで使いたい場合は同期先を確認してください。

予定には無期限の繰り返しはありません。重複を避けるため同じ UID を使いますが、アプリによって再読み込み時の扱いが異なるため、同じ期間を何度も取り込む前に既存予定を確認してください。不要になった場合は専用カレンダーを削除するとまとめて消せます。

夏時間で存在しない時刻はエラーになります。秋の時計戻しで同じ時刻が 2 回ある場合は最初の時刻を使います。時刻の調整が必要な場合は別の時刻を指定してください。

## テスト

合成 XML だけを使用し、個人のデータや実際のカレンダーには触れません。

```sh
python3 -m unittest -v test_toolkit.py
```

重なる睡眠段階、UTC オフセット、夏時間、単位変換、重複ソース、欠損値、CLI の終了状態、ICS の UTF-8 行折り、通知の有無を確認します。

## データの扱い

健康データは慎重に保存してください。XML・CSV と作業用フォルダは公開リポジトリや共有リンクに置かないでください。このツールはデータを送信しませんが、出力先フォルダのクラウド同期や表計算アプリの共有設定は自身で確認する必要があります。データを削除する場合、元の ZIP / XML、出力 CSV、OS のごみ箱やバックアップにもコピーがある可能性があります。
